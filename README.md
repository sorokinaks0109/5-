# Идейные игры — «Пять вершин»

Веб-приложение для онлайн-отборочного тура юбилейного (5 лет) конкурса «Идейные игры».
Каждый участник — альпинист, который в одиночку проходит маршрут из пяти вершин и набирает высоту (баллы) — до 5000 м.

| Вершина | О чём | Как проверяется |
|---|---|---|
| 1. Зоркий глаз | 8 видов потерь | автоматически |
| 2. Порядок в лагере | 5С: порядок шагов, нарушения на картинке, сопоставление | автоматически |
| 3. Тропа потока | поток создания ценности: собрать процесс, найти операции без ценности, посчитать экономию | автоматически |
| 4. Разбор завала | «5 почему», корневая причина, меры, регулярный менеджмент | автоматически |
| 5. Юбилейная | своя идея по шаблону | жюри из 3 человек, 5 критериев |

Роли: **участник** (вход по личному коду), **жюри** (анонимные идеи этапа 5), **организатор** (коды, тур, прогресс, итоги, выгрузка в Excel).

> Все задания в банке — **ЧЕРНОВИК**: цифры, названия складов и посёлков условные. Перед настоящим туром их нужно проверить и заменить.

## 1. Посмотреть демо

Демо-режим работает без базы данных: все данные хранятся в браузере. Он нужен, чтобы показать игру и проверить задания.
В демо уже есть 14 «ботов» с результатами — на горе рейтинга видны флажки.

**Самый простой способ** — опубликовать сайт (раздел 2): без настроек Supabase он сам соберётся в демо-режиме.

**На своём компьютере:**

1. Установите Node.js версии 22 или новее: https://nodejs.org (кнопка «LTS», установка «Далее → Далее»).
2. Скачайте проект: на странице репозитория на GitHub нажмите зелёную кнопку **Code → Download ZIP** и распакуйте архив.
3. Откройте папку проекта в терминале:
   - Windows: откройте папку в Проводнике, в адресной строке наберите `cmd` и нажмите Enter;
   - Mac: правой кнопкой по папке → «Службы» → «Новый терминал по адресу папки».
4. Выполните по очереди:
   ```
   npm install
   npm run dev
   ```
5. Откройте в браузере адрес, который появится в терминале (обычно http://localhost:5173).

На экране входа есть кнопки с демо-кодами:

| Роль | Коды |
|---|---|
| Участник | `DEMO-0001` … `DEMO-0005` |
| Жюри | `JURY-0001`, `JURY-0002`, `JURY-0003` |
| Организатор | `ORG-2027` |

Демо можно сбросить: войдите как организатор → вкладка «Тур» → «Сбросить демо».

Чтобы в демо увидеть итоги и сертификат: организатор → «Закрыть тур» → «Опубликовать итоги», потом войдите участником.
Учтите: участник, который не заполнил профиль до публикации итогов, после неё профиль уже не заполнит.

> ⚠️ Демо **нельзя** использовать для настоящего тура: в нём правильные ответы находятся в браузере, а данные видны только на одном компьютере.

## 2. Опубликовать сайт на GitHub Pages

Публикация полностью автоматическая: после каждого изменения в ветке `main` GitHub сам прогоняет тесты, собирает и выкладывает сайт.

1. Репозиторий на GitHub → **Settings → Pages**.
2. В поле **Source** выберите **GitHub Actions**.
3. Убедитесь, что код находится в ветке `main` (если работа велась в другой ветке — слейте её через Pull request).
4. Откройте вкладку **Actions** → слева «Сайт» → **Run workflow** (или просто сделайте любое изменение в `main`).
5. Через 1–2 минуты сайт появится по адресу `https://<ваш-логин>.github.io/<имя-репозитория>/`.
   Точный адрес виден в Settings → Pages и в результате запуска в Actions.

Пока Supabase не подключён (раздел 3), сайт работает в **демо-режиме**.

## 3. Подключить Supabase (боевой режим)

Supabase — это бесплатная база данных с сервером. В боевом режиме правильные ответы хранятся только на сервере, а проверка идёт там же.
Займёт примерно 30–40 минут. Ничего программировать не нужно — только скопировать значения из одного места в другое.

### Шаг 1. Создайте проект

1. Зарегистрируйтесь на https://supabase.com (можно через GitHub).
2. **New project**. Название — любое, например `idei-igry`. Придумайте и сохраните пароль базы данных. Регион — ближайший (например, Central EU).
3. Подождите 1–2 минуты, пока проект создаётся.

### Шаг 2. Создайте таблицы

1. В меню слева — **SQL Editor** → **New query**.
2. Откройте в репозитории файл `supabase/schema.sql`, скопируйте его целиком и вставьте.
3. Нажмите **Run**. Должно появиться «Success. No rows returned».

### Шаг 3. Настройте вход

1. **Authentication → Sign In / Providers**:
   - **Email** должен быть включён (через него работает вход по коду; писем никто не получает);
   - выключите **Allow new users to sign up** — новые учётные записи создаёт только организатор.
2. **Authentication → Rate Limits**: увеличьте лимит **sign-ups and sign-ins** до 300–500 за 5 минут.
   Это важно: в корпоративной сети у всех сотрудников один внешний IP-адрес, и стандартного лимита (30 входов) не хватит.

### Шаг 4. Задайте код организатора

1. **Edge Functions → Secrets** (или Project Settings → Edge Functions) → **Add new secret**.
2. Имя: `ORGANIZER_CODE`, значение — придумайте код не короче 8 символов (латинские буквы и цифры), например `ORG7K2P9QX`.
   Этим кодом вы будете входить как организатор. Никому его не передавайте.

### Шаг 5. Скопируйте ключи

1. **Project Settings → API** (или «Data API» и «API Keys»):
   - **Project URL** — адрес вида `https://abcdefgh.supabase.co`;
   - **anon public** (или **publishable**) key — длинная строка. Это открытый ключ, его можно показывать.
   - ⚠️ ключ **service_role / secret** никуда не копируйте.
2. **Project ref** — это часть адреса проекта: в `https://abcdefgh.supabase.co` это `abcdefgh`.
3. Токен доступа: нажмите на аватар справа вверху → **Account preferences → Access Tokens → Generate new token**. Назовите `github`, скопируйте.

### Шаг 6. Передайте ключи в GitHub

Репозиторий → **Settings → Secrets and variables → Actions**.

Вкладка **Secrets** → **New repository secret** (секреты никто не увидит):

| Имя | Значение |
|---|---|
| `SUPABASE_ACCESS_TOKEN` | токен из шага 5.3 |
| `SUPABASE_PROJECT_REF` | project ref из шага 5.2 |

Вкладка **Variables** → **New repository variable**:

| Имя | Значение |
|---|---|
| `SUPABASE_URL` | Project URL из шага 5.1 |
| `SUPABASE_ANON_KEY` | anon / publishable key из шага 5.1 |

### Шаг 7. Опубликуйте

1. **Actions** → «Сервер Supabase» → **Run workflow**. Дождитесь зелёной галочки: серверная функция `game` опубликована.
2. **Actions** → «Сайт» → **Run workflow**. Теперь сайт собирается в боевом режиме (на экране входа пропадёт блок «ДЕМО-РЕЖИМ»).
3. Откройте сайт и войдите кодом организатора из шага 4.

Дальше всё работает само: при изменении заданий в `content/content.json` обе публикации запускаются автоматически.

### Если что-то не работает

- **«Код не найден» у организатора** — проверьте секрет `ORGANIZER_CODE` (шаг 4) и что функция опубликована (шаг 7.1).
- **«Ошибка сервера»** — Supabase → Edge Functions → `game` → Logs: там видна причина.
- **«Слишком много попыток»** — увеличьте лимит (шаг 3.2).
- **Бесплатный проект Supabase «засыпает»**, если им не пользоваться 7 дней. Перед туром зайдите в панель Supabase и, если проект на паузе, нажмите **Restore**. Во время тура он не уснёт.

## 4. Как менять задания

Все задания, тексты и настройки лежат в одном файле: **`content/content.json`**. Программировать не нужно.

**Как редактировать прямо на GitHub:** откройте файл → значок карандаша (Edit) → внесите правки → **Commit changes**.
После сохранения GitHub сам проверит файл (тесты) и опубликует изменения. Если в файле ошибка, в **Actions** будет красный крестик, а в журнале — понятный список, что не так (например: «stage1, ситуация sit-05: вид потерь "ожыдание" не найден»). Сайт при этом не сломается — останется предыдущая версия.

### Правила формата JSON

- Текст всегда в двойных кавычках: `"text": "Машина ждёт у ворот"`.
- Между элементами — запятая, после последнего элемента запятой **нет**.
- Кавычки внутри текста — «ёлочки» или `\"`.
- Проверить файл можно на https://jsonlint.com (вставить и нажать Validate).

### Настройки тура — раздел `settings`

```json
"settings": {
  "maxParticipants": 150,          // сколько кодов участников можно создать
  "tourDays": 7,                   // на сколько дней открывается тур
  "stageMinutes": [15, 15, 15, 15, 40],  // минуты на вершины 1–5
  "finalistsCount": 20,            // сколько человек выходит в финал
  "hintsTotal": 3,                 // подсказок на весь тур
  "hintPenalty": 0.3,              // штраф за подсказку: 0.3 = 30 %
  "juryCount": 3,                  // сколько судей
  "draw": {
    "stage1Situations": 10,        // сколько ситуаций выпадает на этапе 1
    "stage2Images": 1,
    "stage3Processes": 1,
    "stage4Cases": 1,
    "stage4Questions": 4
  },
  "points": { ... }                // сколько метров за каждую часть этапов 2–4 (сумма = 1000)
}
```

(Комментарии `//` здесь только для пояснения — в сам файл их писать нельзя.)

### Пример: добавить ситуацию на этапе 1

Найдите `"situations": [` и добавьте после любой ситуации (не забудьте запятую):

```json
{
  "id": "sit-21",
  "note": "ЧЕРНОВИК",
  "answer": "waiting",
  "text": "Погрузчик стоит 20 минут: ждёт, пока освободится рампа.",
  "hint": "Что делает погрузчик?",
  "explanation": "Техника простаивает — это ожидание."
}
```

- `id` — любой уникальный код, латиницей;
- `answer` — вид потерь: `overproduction` (перепроизводство), `waiting` (ожидание), `transport` (лишняя транспортировка), `overprocessing` (лишняя обработка), `inventory` (лишние запасы), `motion` (лишние перемещения), `defects` (дефекты), `talent` (нереализованный потенциал);
- `hint` — подсказка (можно не писать — тогда подсказки к заданию нет);
- `explanation` — пояснение, которое участник увидит после этапа;
- `note` — пометка для вас, участники её не видят. Когда задание проверено, можно написать `"note": "ГОТОВО"`.

Банк должен быть больше, чем выдаётся одному участнику: если в `draw.stage1Situations` стоит 10, ситуаций нужно больше 10.

### Пример: заменить картинку на этапе 2

1. Нарисуйте или сфотографируйте склад. Удобный размер — 800×500 точек (соотношение 1,6).
2. Загрузите файл в папку `public/images/stage2/` (на GitHub: Add file → Upload files).
3. В `content.json` в нужной картинке поменяйте `"image": "images/stage2/имя-файла.png"` и `"aspect": 1.6` (ширина ÷ высота).
4. Отметьте зоны нарушений прямоугольниками **в процентах** от ширины и высоты картинки:
   ```json
   { "id": "z-oil", "x": 17, "y": 78, "w": 17, "h": 13, "label": "Масляное пятно на полу" }
   ```
   `x`, `y` — левый верхний угол, `w`, `h` — ширина и высота. Пример: пятно начинается в точке 136×390 на картинке 800×500 → `x = 136 / 800 × 100 = 17`, `y = 390 / 500 × 100 = 78`.
   Координаты точки на картинке показывает любой графический редактор (Paint: внизу окна).
5. В разделе `match` — нарушения для сопоставления со шагами 5С: `sort` (сортировка), `order` (соблюдение порядка), `shine` (содержание в чистоте), `standard` (стандартизация), `sustain` (совершенствование).

Совет: после замены зайдите в демо, пройдите этап 2 — в разборе зоны обведены зелёным, и видно, правильно ли они стоят.

### Пример: процесс для этапа 3

Карточки пишутся **в правильном порядке** — участнику они выдаются перемешанными:

```json
{ "id": "c1", "text": "Машина ждёт у ворот", "minutes": 30, "valueAdded": false }
```

`valueAdded: false` — операция без ценности. Правильный ответ в расчёте считается сам: сумма времени операций без ценности. `savingTolerance` — допуск (± сколько минут засчитывается). `unit` — единица времени: `"мин"` или `"ч"`.

### Пример: кейс для этапа 4

У кейса есть шаги `whys` («почему?» по порядку, у каждого — варианты `options` и правильный `answer`), корневая причина `root` и меры `measures` (несколько правильных `answers`). Вопросы по регулярному менеджменту — в `questions`.

### Этап 5 — поля шаблона и критерии жюри

`stage5.fields` — поля шаблона: `label` (название), `help` (пояснение), `maxLength` (лимит символов), `required: true` (обязательное).
`stage5.criteria` — критерии жюри; сумма `max` должна быть 1000.

### Подразделения

Список `departments` — участник выбирает подразделение из него.

## 5. Как провести тур

**За 2 недели**
1. Проверьте и замените черновые задания (раздел 4). Пройдите все этапы сами в демо-режиме.
2. Подключите Supabase (раздел 3).

**За неделю**
3. Войдите кодом организатора → **Личные коды** → «Создать 150 кодов участников» и «Создать коды жюри».
4. Скачайте список (Excel). В колонке «Кому выдан» впишите сотрудников. **Храните этот файл у себя** — в системе нет ФИО, телефонов и почты.
5. Раздайте коды (лично, в письме, в конверте). Жюри — их коды.
6. Проведите пробный вход с 1–2 коллегами.

**Старт**
7. **Тур → Открыть тур**. Тур открывается на 7 дней (дату закрытия можно изменить).
8. Разошлите ссылку на сайт. Подсказка участникам: каждую вершину можно пройти один раз, таймер не останавливается.

**Во время тура**
9. Вкладка **Прогресс**: кто вошёл, кто на какой вершине.
10. Жюри может оценивать идеи сразу, как они приходят.

**После закрытия**
11. Тур закроется сам в указанное время (или кнопка «Закрыть тур»).
12. Дождитесь, пока все судьи оценят все работы: на вкладке **Итоги** появится предупреждение, если оценок не хватает.
13. **Итоги → Скачать Excel**: листы «Рейтинг», «Жюри», «Идеи». Первые 20 отмечены «финалист».
14. **Тур → Опубликовать итоги**. Участники увидят рейтинг на горе и смогут скачать сертификат «Покоритель вершины».

## 6. Принятые решения

Там, где требования допускали разные толкования, приняты такие решения.

**Честная игра и безопасность**
- Правила игры написаны один раз (`src/core`) и работают и в демо, и на сервере. Проверка ответов в боевом режиме идёт только в серверной функции Supabase.
- В боевой сборке сайта нет заданий и ответов: в браузер попадает только публичная часть `content.json` (названия, тексты, настройки). Задания участник получает с сервера по одному набору, без правильных ответов.
- Защита строк (RLS) включена на всех таблицах: участник читает только свои строки, жюри — только отправленные идеи (без имён) и свои оценки, организатор — всё. Писать в таблицы из браузера не может никто: все изменения делает серверная функция после проверки прав и правил.
- Вход по коду сделан через Supabase Auth: код — это и логин, и пароль. Для входа используется служебный адрес вида `код@codes.idei-igry.example.com`; настоящей почты нет, писем никто не получает.
- Коды хранятся в базе открытым текстом, но видны только организатору — чтобы список можно было скачать повторно.
- Код — 8 символов без похожих знаков (нет 0/O, 1/I/L), вводить можно с дефисом или без, в любом регистре.
- Каждому участнику случайно выпадает свой набор заданий; порядок заданий и вариантов тоже свой. Выдача зависит от секретной «соли» тура, поэтому её нельзя предсказать.

**Ход игры**
- Ответ на каждое задание окончательный и проверяется сразу: участник видит «верно / частично / неверно» и метры, но не правильный ответ. Это нужно для шкалы «погоды». Правильные ответы и пояснения показываются в разборе после завершения этапа.
- Этап завершается: когда решены все задания; кнопкой «Завершить этап»; или по окончании таймера. Если страница закрыта, сервер закроет этап при следующем входе, временем окончания будет время таймера.
- Сервер принимает ответ ещё 10 секунд после окончания таймера — на задержку сети (`graceSeconds`).
- Повторный вход на начатый этап не перезапускает таймер.
- Начать новую вершину после закрытия тура нельзя; начатую можно довести до конца её таймера.
- Погода зависит от доли ошибок на текущей вершине: ясно → облачно → снегопад → метель → буран.
- «5 почему»: шаги решаются по порядку. Вопрос следующего шага содержит предыдущее звено цепочки — иначе метод не работает.
- В сопоставлении «нарушение → шаг 5С» шаги перемешаны, чтобы не подсказывать ответ на задание про порядок шагов.
- На этапе 3 время указано на карточках; экономия = сумма времени операций без ценности (с допуском). Список операций во втором задании показывается в том порядке, который собрал участник.

**Подсчёт метров**
- Частично правильные ответы дают часть метров: порядок — по числу элементов на своих местах; нарушения на картинке — найденные зоны минус половина за каждую лишнюю метку; сопоставление — по верным парам; выбор нескольких вариантов и операции без ценности — (верные − лишние) ÷ число верных (выбрать всё подряд не выгодно); расчёт — верно, если в пределах допуска.
- Подсказка — текст из `content.json`. Её можно взять только до ответа; повторный просмотр той же подсказки бесплатный. Штраф 30 % применяется к метрам за это задание.
- Этап 5: сумма пяти критериев у каждого судьи (до 1000), итог — среднее по судьям, которые оценили работу. Если оценили не все — организатор видит предупреждение. Судьи могут менять оценки до публикации итогов.
- Тай-брейк: суммарное время этапов 1–4; не начатый или не завершённый этап считается за полный лимит (15 минут). Полное совпадение высоты и времени — одно место на двоих.
- Финалисты — первые 20 строк рейтинга с ненулевой высотой.

**Тур и рейтинг**
- У тура три состояния: не открыт → открыт → закрыт. Публикация итогов — отдельная кнопка: так жюри успевает оценить идеи после закрытия тура. Тур закрывается сам в назначенное время.
- Пока итоги не опубликованы, участник видит только свою высоту и своё место, считаемое по этапам 1–4 (оценки жюри ему ещё не видны). Полный рейтинг и сертификат — после публикации.
- Ник уникален (2–24 символа), виден всем в рейтинге. Сменить профиль можно до публикации итогов.
- Лимиты из настроек соблюдаются: больше 150 кодов участников и 3 кодов жюри создать нельзя.

**Этап 5**
- Черновик идеи сохраняется на сервер каждые 15 секунд и дополнительно в браузере. Если время кончилось, жюри получит последний сохранённый черновик (если он не пустой).
- Работа получает случайный трёхзначный номер — по нему нельзя угадать автора или время отправки.
- Обязательные поля: проблема, текущая ситуация, корневая причина, решение, что нужно для внедрения. Поля эффекта (время, деньги, безопасность, качество) — по возможности.

**Оформление и совместимость**
- Шрифт — системный, без загрузки из интернета: корпоративная сеть может блокировать сторонние сервисы.
- Перетаскивание карточек работает пальцем и мышью; на случай неудобства у каждой карточки есть стрелки ▲▼.
- Адреса страниц вида `#/stage/1` — так сайт работает на GitHub Pages без дополнительных настроек.
- Анимации отключаются, если в системе включено «уменьшить движение».
- Место под логотип оставлено пустым и подписано — на экране входа, на главной и в сертификате.

**Демо-режим**
- Включается сам, если при сборке не заданы адрес и ключ Supabase. Данные — в браузере, есть 14 ботов с результатами, 5 кодов участников, 3 кода жюри и код организатора.

## 7. Для разработчика

```
npm install
npm run dev        # демо на http://localhost:5173
npm test           # тесты: баллы, таймер, подсказки, случайная выдача, правила, content.json
npm run build      # сборка в папку dist
```

Боевой режим локально: скопируйте `.env.example` в `.env.local` и впишите `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY`.

Структура — в `PLAN.md`. Коротко:

- `content/content.json` — задания и настройки;
- `src/core/` — правила игры без React и без базы (одинаково в браузере и на сервере);
- `src/api/` — демо-транспорт (localStorage) и транспорт Supabase;
- `src/screens/`, `src/items/`, `src/components/` — интерфейс;
- `supabase/schema.sql` — таблицы и RLS; `supabase/functions/game/` — серверная функция;
- `scripts/prepare-function.mjs` — копирует `src/core` и `content.json` в функцию перед публикацией;
- `.github/workflows/` — публикация сайта и функции.
