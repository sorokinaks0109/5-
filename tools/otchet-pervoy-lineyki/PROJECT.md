# Описание проекта «Отчёт первой линейки»

Документ для продолжения работы в новом чате. Начинать с него, затем `README.md` и `BACKLOG.md`.

## Кто и зачем

Ксения Сорокина — главный специалист ООО «Газпромнефть-Снабжение», Дивизион «Восточная Сибирь»,
помощник директора по совещанию первой линейки. Раньше еженедельный отчёт вели в общем Excel.
Теперь это набор автономных HTML-страниц на общей сетевой папке: руководители заполняют свои отчёты,
помощник собирает свод, директор смотрит. Работает без интернета и без установки.

Как отвечать Ксении: по-русски, просто, без канцелярита и штампов; текст — сразу текстом;
слабую идею — называть слабой.

## Ограничения (не нарушать)

- **Данные компании не выходят за периметр.** Никакого внешнего хостинга, облаков, внешних сервисов.
  Все страницы — локальные файлы на общей папке. Ксения: «я рисковать не буду».
- **Сетевые диски не подключать** (за это могут наказать) — папку выбирают в браузере через
  File System Access API, ничего не монтируется.
- **Данные компании не коммитить.** `.gitignore`: `*.xlsx`, `*.json` (кроме `package.json`).
  Тестовые данные живут только в scratchpad.
- **Обновление не теряет данные:** заменяются только `.html`, папка `Данные` не трогается,
  перед заменой — копия `Данные`. Новая версия обязана читать данные старого формата как есть.
- В тексте для портала инициатив и т. п. описывать честно: «электронный отчёт на корпоративной папке».
- В коммитах не указывать модель; ветка разработки `ccr-52202e32-evpzeq`; PR — только по просьбе.

## Модель данных (главное)

- `reg.people[]` — люди. `onMeeting`: да / нет / `extra` («только план и УПЦ» — лидеры команд,
  которые не в первой линейке, например директор как лидер команды). `extra` не попадают в совещание,
  своды, напоминания; их страница упрощённая (только УПЦ и план).
- `reg.memos[]` — поручения. `m.resps[]` — несколько ответственных, у каждого свой статус;
  общий прогресс «выполнили 5 из 9». Соисполнители пишут `coNotes` в своих данных, ответственный их видит.
- `reg.kpis[]`, `reg.events[]` — карта УПЦ. Ручные показатели сохраняются при загрузке новой карты.
  Мероприятие можно перенести к другому показателю, сменить докладчика (старый статус уходит в `ev.prev`).
- `ev.override` — статус, проставленный из АВР; действует, пока докладчик не сохранит своё позже.
- `reg.settings`: `sections` (переименовать/скрыть разделы — скрываются, а не удаляются),
  `avrReq` (запрос «итог за квартал»), `mailMode` + `owaUrl`, `avrMap`/`avrExcluded`
  (выученные связи строк АВР), `lastExport`, `history` (статистика по неделям, 104 недели).
- `reg.plan` — план на следующий год: `{year, on, due, text, kpis[], events[]}`.
- Данные руководителя: `memo`, `events`, `kpi`, `ros`, `proj`, `coNotes`, `avrq['период|evId']`,
  `planK`, `planBI`, `saveId`/`saveIds`.

## Как это работает

**Два режима у одной страницы руководителя.**
Astra/Chromium — «Сохранять сразу в папку» (доступ к папке). Windows — режим «файлом»: данные вшиты
в страницу, сохранение — JSON-файлом в «Входящие», помощник принимает. Отчёт, который заполняют люди
на разных системах (офис Хисматуллина: Кондратьева в Тюмени на Windows), — одна страница.

**Слияние.** Трёхстороннее: база (с чего человек начал), его версия, текущая (`Model.mergeReport`).
Поручения и мероприятия — по полям, комментарии к показателям, `coNotes`, `avrq`, `planK` — по ключам,
РОС/проекты/`planBI` — целиком, вложения — по имени файла. Последний сохранивший не затирает чужое.

**Неделя.** Руководители заполняют → помощник проводит совещание (фильтры, экран по людям) →
«Отправить директору»: открывается письмо в OWA, версия для телефона кладётся в «Своды»,
файл прикрепляется вручную → «Мемо после совещания» всем + Excel в «Своды». Напоминания — из OWA.

**План АВР (квартал).** Управление присылает xlsx. Вкладка «План АВР»: загрузить файл → строки
сопоставляются с мероприятиями отчёта (сохранённая связь → тот же показатель и текст → похожий текст
внутри показателя) → помощник сверяет файл и отчёт, выбирает статус → «Сохранить» пишет новую колонку
квартала в файл (только лист дивизиона, только нужные ячейки, формулы не трогаются) и примечания →
«Отправить исполнителям» проставляет выбранные статусы через `override`. Работа сохраняется
в `Данные/АВР/`, исключённые строки и связи запоминаются на следующие кварталы.

**Квартальный итог.** В настройках включается запрос «итог за квартал»: у руководителей появляется
поле по каждому мероприятию, у помощника — прогресс заполнения.

**План на следующий год.** Мероприятия формирует сам дивизион (лидеры команд, до 20 декабря).
Вкладка «План на год»: скопировать мероприятия этого года (даты +1 год) → лидеры подтверждают,
правят, добавляют у себя → выгрузка в форму «Приложение 3» (Excel) → напоминания.

**Защита данных.** Каждая запись проверяется перед сохранением; при порче файла загрузка берёт
последнюю дневную копию из архива и сообщает об этом; еженедельные копии; кнопка выгрузки
`Данные` в zip (помощник напоминает раз в неделю); `.crswap` старше часа удаляются при открытии
(это временные файлы Chromium от прерванной записи).

**Графики директору.** 1 — статусы поручений по руководителям, 2 — выполнение мероприятий УПЦ
по показателям. HTML/CSS без скриптов (работают и в версии для телефона). Цвета:
выполнено #2e8b57, в работе #3b78c4, не выполнено #c8423a, без статуса #e0a800, неактуально #9aa6b2.

**Комментарии директора.** Директору оставлен только просмотр. У каждого пункта отчёта
(поручение, мероприятие, показатель, раздел, отчёт целиком) есть кнопки «Комментарий», «На совещание»
и «Снять с контроля» (последняя только у поручений). Они открывают письмо `mailto:` (у директора Windows и Outlook)
помощнику по поручениям (`reg.settings.asst = {fio, email}`, сейчас это Златковская Ю.) с кодом
`[код D|тип|вид|id|pid]`. Помощник вставляет текст письма во вкладку «Директор», нажимает «Разобрать», затем «Внести».
Комментарий, сказанный на совещании, вносится кнопкой «+ комментарий директора» у пункта.
`reg.dirNotes[]`; ответ руководителя хранится в его файле `dirAns[id]`. Комментарий висит красным, пока нет ответа;
закрывает его помощник. «На совещание» ставит пункт первым и закрывается кнопкой «Совещание прошло».
«Снять с контроля» решает помощник, в `closed.why` пишется «по решению директора».

**Требуют внимания и что изменилось.** `reg.track` хранит по каждому пункту, с какого дня не меняется
статус и пояснение (`since`), а также число переносов срока. Помощник обновляет `reg.track` при открытии страницы.
Если пояснение поменяли позже, это видно по хешу. Причины попадания в список:
- пояснение не менялось 3 недели и больше;
- срок прошёл без движения;
- срок переносили 2 раза и больше;
- статус есть, а пояснения нет.

Снимок статусов делается кнопкой «Совещание прошло сегодня», от него считается «что изменилось».
У директора есть «Карточка руководителя»: просрочки, «требуют внимания», комментарии за 3 месяца, дисциплина за 13 недель.

## Решения и почему

- **OWA, а не `mailto:`** — `mailto` открывает Р7. Ссылка `…/owa/?path=/mail/action/compose&to=&subject=&body=`.
  Длина ссылки ≤ 1900 (кириллица раздувается ×6, длиннее — ошибка OWA); длинный текст кладётся
  в буфер обмена, в письме — короткий. Окно открывается **сразу по нажатию**, до любой асинхронной
  работы, иначе браузер блокирует; `about:blank` заранее не открывать.
- **Точечная правка xlsx АВР** (JSZip + DOMParser, `inlineStr`, `createFolders:false`), а не пересборка
  ExcelJS — файл управления должен остаться таким же, кроме нужных ячеек.
- **`override` + `prev`** вместо перезаписи данных руководителя — помощник не пишет в чужие файлы.
- **Разделы скрываются, а не удаляются** — данные остаются, можно вернуть.
- **Статус `extra`** вместо отдельного списка — один реестр людей, но такие люди нигде не мешают.
- Нормализация текстов при сопоставлении: без номера в начале, без «срок: …», без префикса «В работе.»;
  `\b` с кириллицей не работает — использовать `\s`.

npm i
python3 migrate.py src.xlsx new.xlsx "out/Отчёт первой линейки"   # тестовые данные
node build.mjs "out/Отчёт первой линейки"

Chromium в облачной среде: `/opt/pw-browsers/chromium-1194/chrome-linux/chrome`.
Тестовые файлы (`src.xlsx`, `new.xlsx`, `card2.xlsx`, АВР, карта 13.10) — только в scratchpad сессии,
в репозитории их нет; в новом чате их надо попросить у Ксении заново.

Перед выдачей обновления: прогнать тесты на данных старого формата; выдавать архив только с `.html`
и инструкцией «Как обновить и как восстановить».

## Подводные камни

- Атрибуты HTML браузер приводит к нижнему регистру — id показателей класть в значение (`data-pv="…"`).
- Docx в облаке LibreOffice не рендерит — предпросмотр через mammoth + скриншот Playwright.
- Excel-вложения: пустые и скрытые колонки убираются, иначе текст ломается «по букве».
- В АВР строка подписи под таблицей («Директор …») — не мероприятие.
- Сравнение команды в карте УПЦ — без учёта порядка.
